# Cashback Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The cashier types the customer's phone when closing a bill; the customer earns cashback in R$ and uses it as a discount on a later bill; the CRM shows what each customer bought.

**Architecture:** Pure rules in `lib/cashback/rules.ts`; all writes in `lib/cashback/service.ts`, called inside the existing bill-close, reopen/cancel and kitchen-order-complete transactions. The bill (`loadBill`) subtracts `OrderSession.cashbackUsedCents`; the DRE adds it back as a deduction line; the NFC-e apportions it as item discounts.

**Tech Stack:** Next.js 14 app router, Prisma + PostgreSQL, Jest (unit: `npm run test:unit`; integration: `npx jest --config jest.integration.config.js --workerIdleMemoryLimit=10MB <path>`).

**Spec:** `docs/superpowers/specs/2026-10-23-cashback-design.md` (§4 a–d approved by the owner on 2026-10-23).

## Global Constraints

- Money in integer cents; credit = `floor(baseCents × percent / 100)`.
- Defaults: `percent` 5, `validityMonths` 6, `minUseCents` 1000, `enabled` true. Limits: percent 0,5–30, validity 1–24 months, minUse 0–100000.
- Base of the credit = paid for the items: bill subtotal − cashback used. Never the service charge, never the delivery fee.
- Cashback (earn and use) only where `isTierFeatureEnabled(tier, 'loyalty')` (Business, Enterprise, the 30-day trial). Phone → customer link and CRM totals on every plan.
- Delivery site: earns only (spec §4.a). Use only at Vender (bill) by a staff member.
- Phone: digits only, 10 or 11 digits (DDD + number); a leading 55 with 12–13 digits is stripped.
- Segment (read time, last 90 days of purchases): VIP ≥ 10, Regular 3–9, Ocasional 1–2, Inativo = no purchase in 90 days.
- Every user-facing text in Portuguese; help article + AI knowledge updated in the same work (memory rule).

## Review Focus

- Two staff closing/using on the same bill at once: the use must be taken under the existing comanda lock (`lockComanda`) and the balance read inside the transaction, or the same credit is spent twice → test in Task 3.
- A bill whose cashback use exceeds what is left to pay after a partial payment: the use is capped at `remainingCents` → test in Task 3.
- Reopening a bill whose credit was already partly spent: reverse only `remainingCents`, report the rest, never a negative balance → test in Task 3.
- The same phone in two restaurants: two customers, balances never mix → test in Task 2.
- An offline counter sale replayed twice: credited once (unique `orderSessionId` on CashbackCredit) → test in Task 4.

### Task 1: Schema, migration and pure rules

**Files:**

- Test: `__tests__/unit/cashback-rules.test.ts`

**Interfaces — Produces:**
- Customer: `email String? @unique`, `phoneDigits String?`, `@@unique([restaurantId, phoneDigits])`.
- OrderSession: `customerId String?` (relation `Customer`), `cashbackUsedCents Int @default(0)`.
- `CashbackSettings { restaurantId @unique, enabled Boolean @default(true), percent Decimal(5,2) @default(5), validityMonths Int @default(6), minUseCents Int @default(1000) }`.
- `CashbackCredit { id, restaurantId, customerId, orderSessionId String? @unique, orderId String? @unique, amountCents Int, remainingCents Int, expiresAt DateTime, reversedAt DateTime?, createdAt }`, index `[restaurantId, customerId]`.
- `CashbackUse { id, restaurantId, customerId, orderSessionId String @unique, amountCents Int, allocations Json /* [{creditId, cents}] */, reversedAt DateTime?, createdAt }`.
- `normalizePhone(raw: unknown): string | null`
- `creditCents(baseCents: number, percent: number): number`
- `allocateUse(credits: Array<{ id: string; remainingCents: number; expiresAt: Date; createdAt: Date }>, cents: number, now: Date): Array<{ creditId: string; cents: number }>` — oldest `createdAt` first, skipping expired; throws `Error('Saldo insuficiente')` if the sum is short.
- `apportionDiscount(itemCents: number[], discountCents: number): number[]` — proportional, floor, remainder on the last item with value; sum equals discount; never above an item.
- `segmentOf(purchases90d: number): 'VIP' | 'REGULAR' | 'OCCASIONAL' | 'INACTIVE'`
- `parseSettings(body): { ok: true; data } | { ok: false; error: string }` with the limits above (accepts "5,5").

### Task 2: Cashback service and customers by phone

**Files:**
- Create: `lib/cashback/service.ts`
- Test: `__tests__/integration/cashback/service.test.ts`

**Interfaces — Consumes:** Task 1. **Produces:**
- `getCashbackSettings(restaurantId): Promise<{ enabled; percent: number; validityMonths; minUseCents; available: boolean /* plan allows */ }>` (defaults when no row).
- `saveCashbackSettings(member, body)` → uses `parseSettings`, upsert, `recordAudit`.
- `findCustomerByPhone(db, restaurantId, phoneDigits)` and `upsertCustomerByPhone(db, restaurantId, phoneDigits, name?: string | null)` → creates with `phone` formatted and `phoneDigits`; name required when new (`CashRuleError('Informe o nome do cliente', 400)`).
- `balanceCents(db, restaurantId, customerId, now = new Date()): Promise<number>`
- `creditSale(tx, { restaurantId, customerId, baseCents, orderSessionId?: string, orderId?: string, now? }): Promise<number>` — no-op (0) when not available/disabled/base ≤ 0; unique source makes a repeat a no-op.
- `useOnSession(tx, { restaurantId, customerId, orderSessionId, cents, now? })` — FIFO from `allocateUse`, decrements credits, writes CashbackUse, sets `OrderSession.cashbackUsedCents`.
- `removeUse(tx, restaurantId, orderSessionId)` — restores allocations, marks reversed, sets `cashbackUsedCents` 0.
- `reverseForSession(tx, restaurantId, orderSessionId): Promise<{ notReversedCents: number }>` — reverses the session's credit (remaining only) and its use.
- `recordPurchase(tx, customerId, totalCents, at)` / `undoPurchase(tx, customerId, totalCents)` — Customer totals and `averageTicket`.
- `customerPurchases90d(restaurantId, customerId, now)` — closed sessions + completed orders with that customer in 90 days.
